# Transferable Techniques from Adjacent Domains

## Summary

MTG draft pick prediction is structurally a "context-conditioned set scoring" problem: encode the current pool (and optionally the pack/seen signals), then rank a variable candidate set (the current pack), ideally generalizing to cards never seen in training. Several adjacent domains have already solved isomorphic sub-problems. The single most direct transfer is the MTG-native Contextual Preference Ranking (CPR) work, which casts the pick as a Siamese triplet-loss problem ("card p is a better addition to pool C than card n"), and the follow-up "Generalised Card Representations" work, which swaps card-ID embeddings for content-derived features (numeric/nominal stats, sentence-transformer text embeddings, card-image autoencoders, and third-party meta usage vectors) to reach ~55% accuracy on completely unseen cards versus a ~24% random-representation baseline. From cold-start recommendation, two-tower/dual-encoder retrieval gives the canonical recipe for unseen-item generalization: build the candidate tower from content features (not learnable IDs) so new items are embeddable at inference with no retraining. From session-based recommendation, SASRec/BERT4Rec contribute the attention-over-context-set encoder plus a shared item-embedding scoring head (logits = dot product of context embedding with each candidate embedding), which naturally handles a variable candidate set. From game-AI drafting, JueWuDraft (MOBA) contributes a value/policy-network + MCTS pattern for long-horizon, order-aware drafting, and Hearthstone-arena RL work contributes self-play value learning for deck-building. Learning-to-rank (pairwise RankNet / listwise) frames the pack as a ranking list and provides the loss functions that match how draft data is actually labeled (one human pick out of N).

## Approaches

### Content-feature two-tower / dual-encoder retrieval (cold-start)  
*Maturity: production-proven*

Two separate encoders map a query/context and each candidate into a shared low-dimensional space; relevance = dot-product/cosine. The candidate tower is built from item CONTENT features (text, images, metadata) rather than learnable per-item ID embeddings, so brand-new items can be embedded and scored at inference with no retraining.

**How it applies:** Directly maps to MTG draft: a 'pool tower' encodes the current collection, a 'card tower' encodes each candidate card in the pack from features (mana cost, color, type, P/T, rules-text embedding, rarity, public pick/win-rate). Because the card tower never sees a card ID, a card from a future set is scored the moment its features exist. Score every card in the variable-size pack independently then softmax/rank over only the present cards. This is the cleanest path to unseen-card generalization and to handling variable candidate-set size.

**Tradeoffs:** Two-tower with no cross-attention sacrifices fine-grained context-candidate interaction (the pool can only influence the candidate via the dot product), which can miss subtle synergies; quality hinges entirely on feature engineering / text-embedding quality; content-only towers tend to underperform ID-embedding models on cards that ARE well-represented in training (memorization vs generalization tradeoff).

### Siamese triplet-loss contextual preference ranking (CPR)  
*Maturity: research-validated*

Instead of scoring a card in isolation, learn an embedding space with triplet loss where the anchor is the current context (deck/pool), the positive is the human-picked card, and the negative is a passed card; loss = max(d(anchor,pos) - d(anchor,neg) + margin, 0). At inference, pick the candidate whose embedding is closest to the pool embedding.

**How it applies:** This is the MTG-native formulation (Bertram et al. 2021) and is exactly 'encode context set + score candidate set'. It turns each historical pick into many (pool, picked, passed) triplets, which is data-efficient and matches how draft data is naturally labeled (the chosen card was preferred over every other card in the pack). Swapping the one-hot card encoder for a content-feature encoder (as in the 2024 generalised-representations paper) makes it generalize to unseen cards. Domain-agnostic by design (authors note transfer to team-building / sequential set-addition).

**Tradeoffs:** Triplet mining matters a lot (hard-negative selection drives quality); distance-in-space is not interpretable as similarity, which can confuse debugging; pairwise/triplet objectives optimize relative order, not calibrated pick probabilities, so you need extra calibration if you want true P(pick).

### Generalised content-based card representations (numeric+nominal+text+image+meta)  
*Maturity: research-validated*

Replace learnable card-ID embeddings with representations computed from card content: numeric/nominal attributes, sentence-transformer embeddings of rules text, convolutional-autoencoder embeddings of card images, and third-party meta-usage vectors (pick-rate, win-rate). Feed these into a Siamese deck/card encoder.

**How it applies:** This is the directly-validated answer to the unseen-card requirement for MTG: the 2024 paper reports the input representation has little effect on KNOWN-card accuracy (~67-68%) but huge effect on UNSEEN cards, where Features+Meta+Image reached ~43% on new sets and up to ~55% pretrained, vs ~24% random-representation baseline. Text embeddings of rules text capture card function (e.g., 'flying', 'draw a card') that transfers across sets; meta-usage vectors inject crowd wisdom for cards with public stats.

**Tradeoffs:** Meta-usage features leak future information and are unavailable for truly new cards at release (the moment you most need generalization), so they help benchmarks more than day-one use; image autoencoders add pipeline complexity for modest gains; still well below human-known-card ceiling, and human picks are partly unpredictable (caps achievable accuracy).

### Self-attention sequence encoder with shared-embedding scoring head (SASRec / BERT4Rec)  
*Maturity: production-proven*

Encode the user's interaction history with stacked self-attention blocks (+ position embeddings) to get a context vector; score every candidate next-item as the dot product of the context vector with that item's embedding from a SHARED item-embedding matrix. BERT4Rec adds bidirectional (masked-item) training.

**How it applies:** MTG drafting is a sequence of picks; a pick-order-aware attention encoder over the pool (and over the sequence of packs seen) captures 'why' a pool was built and what it now wants. The shared-embedding dot-product head naturally scores a variable candidate set (just dot the context against the cards currently in the pack). If the shared item embedding is replaced by a content-feature projection (as in cold-start variants), the same scoring head generalizes to unseen cards. Masked-pick (BERT4Rec-style) pretraining is a strong self-supervised objective on unlabeled draft logs.

**Tradeoffs:** Vanilla SASRec/BERT4Rec memorize item IDs and do NOT generalize to unseen items unless explicitly modified to content features; attention over a small pool (<45 cards) may be overkill versus simpler pooling; position/sequence signal in draft is weaker than in browsing sessions (pool is more set-like than strictly sequential).

### Policy/value network + MCTS for long-horizon drafting (JueWuDraft, MOBA)  
*Maturity: research-validated*

Train a win-rate predictor on complete lineups, then use a policy+value network to guide Monte-Carlo Tree Search (PUCT) over the draft tree, with a long-term value mechanism summing win-rate across future rounds. Scales to 100+ heroes where exact minimax is intractable.

**How it applies:** Addresses the part of drafting that single-pick prediction ignores: a draft is a sequential decision process where the value of a pick depends on future picks and the final deck's strength. For MTG, a 'deck-strength/win-rate' evaluator over a finished pool can serve as the value function, and lookahead (or its distilled policy) can plan picks rather than greedily imitate. The neural-guidance-makes-large-action-spaces-tractable insight transfers to MTG's large card pool.

**Tradeoffs:** Targets win-rate/optimal play, not human-pick imitation (different objective than the stated prediction task); needs a reliable deck-strength evaluator and ideally a game simulator or large outcome dataset; MCTS is expensive vs a single forward pass; hero pool is fixed/known per patch, so the base method does NOT itself solve unseen-item generalization (content features would still be needed).

### Learning-to-rank objectives (pairwise RankNet / listwise) over the pack  
*Maturity: production-proven*

Treat each pack as a ranking list with one positive (the picked card) and N-1 negatives (passed cards). Pairwise (RankNet) optimizes correct ordering of pairs; listwise (ListNet/softmax-CE) optimizes the full ordering / top-1 probability.

**How it applies:** This is the natural loss family for draft logs because the label is exactly 'this card was preferred over the others in this pack'. A softmax cross-entropy over only the cards present in the pack (i.e., masked to the candidate set, as Draftsim's NNetBot does by multiplying logits by the pack vector) is a listwise top-1 ranker that handles variable candidate-set size for free. Combine with a content-feature scorer to keep unseen-card generalization. CPR's triplet loss is essentially the pairwise version anchored on context.

**Tradeoffs:** Pairwise loss ignores list-position importance (a wrong pick at the top costs the same as a wrong pick at the bottom); listwise softmax assumes a single 'correct' pick when human picks are noisy/multi-modal; ranking losses give order, not calibrated probabilities.

### Self-play reinforcement learning for CCG deck/draft building (Hearthstone arena)  
*Maturity: experimental*

Learn drafting policies via self-play RL where the agent drafts a deck then plays it; the win signal trains the drafting value function. Variants differ in how they encode the already-drafted pool when picking the next card.

**How it applies:** Provides an objective-grounded alternative to imitation: instead of predicting the human pick, learn what actually wins, then optionally distill that into pick scores. Relevant for MTG when you want a strong bot rather than a human-mimic, and the 'how to represent past picks when scoring the next card' design question studied there maps directly to MTG pool-encoding choices.

**Tradeoffs:** Requires a playable game simulator/engine (MTG's rules are vastly more complex than Hearthstone arena, making faithful simulation very hard); optimizes win-rate not human-pick accuracy; sample-inefficient; base formulations use fixed card sets, so unseen-card generalization still needs content features.

## Recommendations

- Adopt the MTG-native recipe as your backbone: Contextual Preference Ranking (triplet loss, pool=anchor, picked vs passed) using the generalised CONTENT-feature card encoder (rules-text sentence embeddings + numeric/nominal stats), which is the only approach with published unseen-card numbers (~55%).
- Architect it as a content-feature two-tower model: a pool tower and an ID-FREE card tower built from features, scored by dot product. This is the single most important design choice for unseen-card generalization — never let a card-ID embedding into the candidate path.
- Handle the variable candidate set with a masked listwise softmax over only the cards present in the current pack (the Draftsim 'multiply logits by pack vector' trick) and train with a learning-to-rank top-1 / pairwise loss, since draft labels are exactly 'picked over the rest of the pack'.
- Use rules-text embeddings as the primary generalization signal; treat meta usage stats (pick/win-rate) as optional features and exclude them from any 'true unseen card at release' evaluation, since they are unavailable/leaky for brand-new cards.
- Consider BERT4Rec-style masked-pick self-supervised pretraining on large unlabeled draft logs, then fine-tune on human picks; add light self-attention over pick-order if you want sequence awareness, but benchmark against simple mean/sum pooling first since the pool is more set-like than sequential.
- If you later want a strong (not human-mimicking) bot, layer a JueWuDraft-style value network + lookahead on top of a learned deck-strength evaluator — but keep this separate from the human-pick-prediction model, as they optimize different objectives.
- Always report seen-card vs unseen-card accuracy separately against the random-representation baseline (~24%) and acknowledge the human-pick noise ceiling; aggregate accuracy hides whether you actually generalize.

## Open questions

- What is the best content encoder for card rules text for transfer — general sentence-transformers, a domain-tuned LLM embedding, or a structured oracle-text parser — and how much does each close the seen-vs-unseen gap?
- Can two-tower (no cross-attention) capture MTG synergies (archetype/color/curve interactions) well enough, or is a cross-attention re-ranker over the pack needed, and at what latency cost?
- How to combine the generalization of content features with the accuracy of ID embeddings (e.g., hybrid towers, residual ID embeddings that decay for rare/new cards) without reintroducing the cold-start failure?
- Is imitation (human-pick accuracy) the right target, or should the objective be deck win-rate via an RL/value approach — and can the two be combined (imitation pretraining + RL fine-tuning)?
- How well do techniques validated on MOBA/Hearthstone (fixed, known item pools per patch) actually transfer once the requirement is truly unseen items, given those base methods do not address cold-start?
- How to evaluate genuine zero-shot generalization fairly given that public meta-usage features leak information and are unavailable at a new set's release — what is the right 'release-day' benchmark protocol?

## Sources

- [Learning With Generalised Card Representations for Magic: The Gathering (Bertram et al., 2024)](https://arxiv.org/pdf/2407.05879) *(paper)* — Replaces card-ID embeddings with content features (numeric/nominal, sentence-transformer text, conv-autoencoder image, meta usage). Known-card accuracy ~67-68% is insensitive to representation, but unseen-card accuracy jumps: Features+Meta+Image ~43% on new sets, up to ~55% pretrained, vs ~24% random baseline. Siamese deck/card encoder with triplet loss into a 512-d space; pick = nearest candidate to deck embedding.
- [Predicting Human Card Selection in MTG with Contextual Preference Ranking (Bertram et al., 2021)](https://arxiv.org/pdf/2105.11864) *(paper)* — Siamese network with triplet loss frames the pick as 'card p is a better addition to deck C than card n'. Anchor=current deck (count vector), positive/negative=candidate cards; inference picks the candidate with minimal Euclidean distance to the deck embedding. Authors state the method is domain-agnostic for sequential set-addition problems.
- [AI Solutions for Drafting in Magic: the Gathering (Ward et al. / Draftsim, 2020)](https://arxiv.org/pdf/2009.00655) *(paper)* — Defines the draft-prediction task and baselines: collection count-vector + pack indicator-vector; NNetBot (3 dense layers, softmax over all 265 cards, logits multiplied by the pack vector to enforce legality) reaches 48.67% top-1 on M19, beating Bayes (43.4%) and heuristic (44.5%). Explicitly names unseen-card / cross-set generalization as future work.
- [Which Heroes to Pick? Learning to Draft in MOBA Games with Neural Networks and Tree Search (JueWuDraft, IEEE ToG 2021)](https://arxiv.org/abs/2012.10171) *(paper)* — Supervised win-rate predictor over complete 10-hero lineups + policy/value network guiding PUCT-MCTS over the draft tree, with a long-term value mechanism summing win-rate across future rounds. Neural guidance keeps the large action space (100+ heroes) tractable where minimax is not; optimizes win-rate, not human imitation.
- [Self-Attentive Sequential Recommendation (SASRec, Kang & McAuley, ICDM 2018)](https://www.semanticscholar.org/paper/Self-Attentive-Sequential-Recommendation-Kang-McAuley/97faeefa771e8cc8e55159e2bd03e6f5eef249a8) *(paper)* — Stacked self-attention blocks with position embeddings encode the interaction-history context; candidate next-items are scored by dot product with a shared item-embedding matrix (left-to-right next-item prediction). The shared-embedding dot-product head is exactly the 'score a variable candidate set' pattern; swapping IDs for content features enables cold-start.
- [BERT4Rec: Sequential Recommendation with Bidirectional Encoder Representations from Transformer (Sun et al., 2019)](https://arxiv.org/pdf/1904.06690) *(paper)* — Bidirectional (masked-item / cloze) self-attention over the interaction sequence; provides a strong self-supervised pretraining objective (predict masked picks) that transfers to draft logs and a context encoder usable with a shared-embedding scoring head.
- [A Flexible Two-Tower Model for Item Cold-Start Recommendation](https://www.researchgate.net/publication/376819594_A_Flexible_Two-tower_Model_for_Item_Cold-start_Recommendation) *(paper)* — Two-tower/dual-encoder where the item tower relies on content features rather than learnable IDs, so new items are embeddable and servable immediately without retraining — the canonical cold-start recipe that maps onto unseen-card scoring in MTG.
- [Exploring reinforcement learning approaches for drafting in collectible card games (Hearthstone arena, ScienceDirect)](https://www.sciencedirect.com/science/article/abs/pii/S1875952122000490) *(paper)* — Self-play deep-RL for arena deck-building; variants differ in how they encode already-drafted cards when picking the next card — directly the 'how to represent the context pool' design question for MTG, and an objective-grounded (win-rate) alternative to imitation.
