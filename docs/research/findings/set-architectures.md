# Set-Based Architectures & Pick Heads

## Summary

The draft pick task is a natural fit for set/attention architectures: the pool of already-picked cards is an unordered, variable-size SET that must be encoded permutation-invariantly, and the pack is a variable-size SET of candidates from which exactly one is chosen. Two families dominate. (1) Set ENCODERS that turn the pool into a context vector: Deep Sets (sum/mean pooling of per-element MLP embeddings, with a universal-approximation guarantee) and the Set Transformer (SAB/ISAB self-attention plus PMA attention pooling), which captures inter-card synergy that plain sum pooling cannot. (2) Candidate-SELECTION heads that produce a probability distribution over the variable pack rather than a fixed-vocabulary softmax: pointer networks and, more generally, content-based attention/cross-attention where the pool context is the query and each pack card is a key — the attention logits ARE the per-card scores, normalized by a softmax whose width equals the current pack size. Crucially, MTG-specific work (Draftsim, Ward et al., Bertram et al.) has already validated these ideas: contextual preference ranking with triplet/InfoNCE losses embeds pool and card in a shared space and scores cards by similarity, and "generalised card representations" (text/numeric/image features instead of per-card ID embeddings) raise accuracy on UNSEEN cards from chance to ~55%, which is the key to generalization beyond the training card set. The dominant production baseline (an MLP over fixed collection/pack vectors with a pack mask) is simple and strong (~70% top-player agreement) but cannot generalize to new cards and ignores intra-pool attention.

## Approaches

### Deep Sets (sum/mean pooling encoder)  
*Maturity: production-proven*

Encodes a set as f(X)=rho(sum_i phi(x_i)): a shared per-element MLP phi embeds each element, a commutative aggregation (sum/mean/max) makes the result permutation-invariant, and a second MLP rho post-processes the pooled vector. Zaheer et al. prove this form is the necessary-and-sufficient structure for permutation-invariant functions (universal approximator for sets up to fixed size), and give a permutation-EQUIVARIANT layer with the tied-weight form Theta = lambda*I + gamma*(1 1^T) for per-element outputs.

**How it applies:** Embed each picked card with a shared encoder phi(card_features), sum/mean to get a fixed pool-context vector regardless of how many cards have been picked (works at pick 1 through 45). To generalize to UNSEEN cards, make phi consume card FEATURES (mana cost, colors, type, P/T, oracle-text embedding) rather than a per-card ID embedding — then any new card maps into the same space (validated by Bertram et al.'s generalised representations, ~55% on unseen cards). Equivariant layers can produce per-pack-card scores directly.

**Tradeoffs:** Cheapest and most robust; trivially handles variable size. But sum/mean pooling is an information bottleneck: it cannot natively model pairwise synergy/anti-synergy among picked cards (e.g. two cards that combo), and equal weighting can drown out a few decisive cards. Often a strong baseline that attention encoders beat on synergy-heavy formats.

### Set Transformer (SAB / ISAB encoder + PMA attention pooling)  
*Maturity: research-validated*

Attention-based permutation-invariant encoder. SAB (Set Attention Block) = multihead self-attention among set elements (permutation-equivariant, models pairwise interactions). ISAB (Induced Set Attention Block) introduces m learned inducing points so attention costs O(n*m) instead of O(n^2). PMA (Pooling by Multihead Attention) replaces sum pooling with k learned seed vectors that attend over the set, giving a learned, content-weighted summary; k=1 yields one invariant embedding. Proven universal approximator for permutation-invariant functions.

**How it applies:** Run SAB/ISAB over the picked pool so cards attend to each other (captures synergy: an aggressive one-drop becomes more valuable in the presence of other aggressive cards), then PMA-pool to a pool-context vector. You can also run self-attention over the PACK so candidates are scored relative to each other, and use cross-attention (pool seeds attend to pack) to produce per-card logits. Strictly more expressive than Deep Sets for the synergy structure that defines good drafting.

**Tradeoffs:** More parameters and compute (still cheap at MTG set sizes ~15 pack / <=45 pool, so ISAB rarely needed). Needs more data to beat Deep Sets and can overfit; the MTG generalised-representations result suggests encoder choice matters less than card-feature representation for raw accuracy, so the synergy modeling is the main payoff.

### Pointer Networks (attention-as-pointer over the candidate set)  
*Maturity: production-proven*

Vinyals et al.: instead of a fixed-vocabulary softmax, a content-based attention mechanism produces, at each step, a softmax over the INPUT positions — the output 'dictionary' size equals the current input length. The decoder state queries each input element; the attention logits define a categorical distribution over the variable input set, from which one element is selected. Originally for combinatorial problems (convex hull, TSP).

**How it applies:** This is the canonical solution to 'output a distribution over a variable candidate set.' Use the pool-context as the query (decoder state) and each pack card embedding as a pointer target; the per-card attention logits become pick probabilities P(card | pool, pack) with the softmax automatically resized to the current pack. No fixed card-vocabulary head, so it natively supports any pack contents — including unseen cards if card embeddings come from features. Picking one card per pack = a single pointer step.

**Tradeoffs:** Simple and exactly matched to the variable-output requirement, but a plain single-query pointer scores each candidate only against the pooled context, not against other candidates; adding pack self-attention before pointing helps. For a one-shot pick (not a sequence) it reduces to a single attention-scoring layer.

### Cross-attention scoring head (pool as query, pack cards as keys/values)  
*Maturity: research-validated*

A general transformer-over-sets formulation: encode pool and pack as sets, then let pool-derived query vector(s) cross-attend to pack card keys; the resulting attention logits (a query.key dot product per card, optionally an MLP on [pool_ctx; card; pool_ctx*card]) are the per-card scores, normalized by softmax over the pack. Equivalent to pointer scoring but framed as cross-attention between the two sets and easily made bidirectional (pack cards also attend to the pool).

**How it applies:** Most flexible draft head: pool encoder (Deep Sets or Set Transformer) -> context; cross-attention assigns each pack card a logit conditioned on the whole pool; softmax over the variable pack gives the pick distribution and trains directly with cross-entropy against the human pick. Naturally yields a probability distribution over exactly the cards present in this pack, and generalizes to unseen cards when card vectors are feature-based.

**Tradeoffs:** Most expressive but the most moving parts; can overfit small sets and needs feature-based card inputs to generalize. Bidirectional pack<->pool attention adds cost but is small at MTG scales.

### Contextual preference ranking — triplet / contextual InfoNCE embedding (MTG-specific)  
*Maturity: research-validated*

Bertram et al.: a contextual preference network embeds the context (pool/deck) and a card into a shared space; training uses triplet loss (chosen card closer to pool-context than not-chosen cards) and later a CONTEXTUAL InfoNCE loss that contrasts the picked card against the SET of unpicked pack cards in one term. This is effectively a learned, variable-width softmax over candidates: it normalizes the preference of one positive against a variable set of negatives, the exact structure of 'one card preferred over the rest of the pack.'

**How it applies:** Directly designed for draft: score(card) = similarity(embed_pool, embed_card); pick = argmax/softmax over pack. The contextual InfoNCE term IS the distribution-over-variable-candidate-set objective, avoiding a fixed softmax and avoiding triplet-mining headaches; reported to beat triplet loss on the collectable-card-game task. Pairs naturally with feature-based card embeddings for unseen-card generalization.

**Tradeoffs:** Requires a contrastive training pipeline and careful negative construction (the InfoNCE variant fixes triplet-mining pain but adds batch-construction subtlety when one positive has multiple positives). Embedding-similarity scoring is slightly less flexible than a full MLP cross-attention head, but is simple, fast at inference, and empirically strong on the CCG task.

### MLP over fixed collection+pack vectors with pack mask (production baseline)  
*Maturity: production-proven*

Draftsim NNetBot / statisticaldrafting.com: represent the pool as a fixed-length 'collection' count vector (one slot per card in the set) and the pack as a binary 'pack' vector; an MLP outputs a card-rating vector over the whole set, masked to the cards present in the pack, then softmax/argmax. This is a Deep-Sets special case where phi is a one-hot lookup and aggregation is summation of counts.

**How it applies:** The current strong, simple baseline: ~70% agreement with top 17lands players, trains in minutes, exports to ONNX for in-browser use. The pack mask is exactly how a FIXED head is restricted to the variable candidate set. But the fixed per-card vocabulary means it CANNOT score cards absent from training — it must be retrained per set and cannot generalize to new cards, which is the precise gap the feature-based set/pointer approaches close.

**Tradeoffs:** Extremely simple, fast to train (~20 min CPU), and a strong accuracy baseline on KNOWN cards. But it is locked to one card set (fixed vocabulary), cannot handle unseen cards, must be retrained per release, and its one-hot count phi discards all card semantics and intra-pool attention/synergy structure.

## Recommendations

- Architecture: pool encoder -> context -> attention/pointer scoring head over the pack. Concretely: encode each card from FEATURES with a shared MLP phi; encode the pool with Deep Sets (mean pooling) or, for synergy, a 1-2 layer Set Transformer (SAB+PMA); then score each pack card via cross-attention/pointer (logit = dot(pool_query, card_key) or MLP([pool_ctx; card; pool_ctx*card])); softmax over the pack and train with cross-entropy on the human pick. This is permutation-invariant on both sets and outputs a distribution sized to the current pack.
- Make the output a variable-width softmax, not a fixed per-card head: compute one logit per card PRESENT in the pack (pointer/attention scoring). This natively handles packs of any size and any card contents, unlike the fixed-vocabulary + mask baseline. The mask trick (Draftsim/statisticaldrafting) is the cheap fallback but locks you to one card set.
- For generalization to UNSEEN cards, this is the single biggest lever (per Bertram et al.): feed card FEATURES (mana value, colors, type line, P/T, rarity, plus an oracle-text embedding from an LLM/sentence encoder, optionally 17lands meta stats) into phi instead of a per-card ID embedding. Encoder choice barely moves known-card accuracy but feature representation is what lifts unseen-card accuracy off chance.
- Start simple and ablate up: (1) Deep Sets mean-pool pool encoder + pointer head as baseline; (2) add pack self-attention so candidates are scored relative to each other; (3) add SAB over the pool only if synergy modeling measurably helps. ISAB inducing points are unnecessary at MTG set sizes (pack <=15, pool <=45).
- Choose the loss to match the candidate-selection framing: plain cross-entropy over the pack softmax is the simplest and corresponds to maximum-likelihood of the human pick; the contextual InfoNCE loss (Bertram et al. 2024) is a drop-in upgrade that contrasts the picked card against all other pack cards and reportedly beats triplet loss while avoiding triplet mining.
- Benchmark against the public bars: ~70% agreement with top 17lands players (statisticaldrafting MLP) for known-card accuracy, and ~55% on unseen cards (generalised representations) as the generalization target. Use 17lands draft logs as training data and report both metrics separately.

## Open questions

- Does explicit pool self-attention (Set Transformer SAB) yield enough synergy-modeling gain over mean-pool Deep Sets to justify the cost on real 17lands data, given Bertram et al.'s finding that encoder choice barely affects known-card accuracy?
- What is the best oracle-text encoder for card features (general sentence-transformer vs. a domain-tuned MTG text model vs. an LLM embedding), and how much does text-feature quality drive the unseen-card accuracy ceiling above ~55%?
- Is contextual InfoNCE robustly better than plain pack-softmax cross-entropy for the single-pick draft objective, and under what data sizes/regimes?
- How should pick context beyond the pool be injected (pick number, pack number, wheel/signal information, what opponents may be drafting) into a set-based scoring head without breaking permutation invariance?
- Can a single feature-based set+pointer model transfer ZERO-SHOT across entirely new MTG sets/formats (not just new individual cards), and how does it compare to per-set retrained fixed-vocabulary MLPs?
- How to calibrate the pack-softmax into trustworthy pick probabilities (vs. just argmax accuracy) for a draft assistant that surfaces close decisions?

## Sources

- [Deep Sets (Zaheer et al., NeurIPS 2017)](https://arxiv.org/abs/1703.06114) *(paper)* — Permutation-invariant functions decompose as f(X)=rho(sum_i phi(x_i)); gives universal-approximation characterization and the tied-weight equivariant layer Theta=lambda*I+gamma*(1 1^T). Foundation for encoding the picked-card pool; sum pooling is a bottleneck that misses pairwise synergy.
- [Set Transformer: Attention-based Permutation-Invariant Neural Networks (Lee et al.)](https://arxiv.org/pdf/1810.00825) *(paper)* — Introduces SAB (self-attention among set elements), ISAB (inducing points, O(n*m) cost) and PMA (learned attention pooling with seed vectors). Attention pooling captures inter-element relationships that sum pooling loses — directly useful for modeling card synergy within the pool and scoring within the pack.
- [Pointer Networks (Vinyals, Fortunato, Jaitly, NeurIPS 2015)](https://arxiv.org/pdf/1506.03134) *(paper)* — Uses content-based attention as a POINTER: output is a softmax over input positions whose size equals the variable input length. This is the canonical way to produce a probability distribution over a variable candidate set (the pack) instead of a fixed-vocabulary softmax.
- [Predicting Human Card Selection in MTG with Contextual Preference Ranking (Bertram et al.)](https://arxiv.org/abs/2105.11864) *(paper)* — Models draft by embedding the deck/pool context and a card jointly and learning preferences with triplet loss; evaluates a card in the CONTEXT of already-selected cards. Direct MTG instantiation of a set-context + candidate-scoring architecture.
- [Contrastive Learning of Preferences with a Contextual InfoNCE Loss (Bertram et al.)](https://arxiv.org/abs/2407.05898) *(paper)* — Adapts InfoNCE so one positive card is contrasted against the SET of other pack cards in one batch term — a learned variable-width softmax over candidates; reported to outperform triplet loss and avoid triplet mining. Maps exactly to 'pick one card preferred over the rest of the pack.'
- [Learning With Generalised Card Representations for Magic: The Gathering (Bertram et al.)](https://arxiv.org/abs/2407.05879) *(paper)* — Replacing per-card ID embeddings with feature-based representations (numeric/nominal stats, card-text embeddings, images, meta usage) barely changes accuracy on KNOWN cards but raises accuracy on UNSEEN cards to ~55%. This is the key to generalization beyond the training card set.
- [AI solutions for drafting in Magic: the Gathering (Ward et al., Draftsim)](https://arxiv.org/pdf/2009.00655) *(paper)* — NNetBot: MLP over a collection vector (pool) and pack vector outputs a per-card rating; was the strongest bot at predicting human picks. Establishes the fixed-vector + pack-mask baseline (a Deep-Sets special case) and its per-set retraining limitation.
- [Statistical Drafting — About (production MTG draft helper)](https://statisticaldrafting.com/about) *(blog)* — Production MLP trained on 17lands: collection vector + pack vector -> 0-100 card ratings, pack vector masks non-pack cards (ones vector at inference), BatchNorm/dropout, ~70% agreement with top players, ONNX in-browser. Concrete reference for the masked fixed-head pattern.
