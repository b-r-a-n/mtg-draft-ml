# Card Representation for Generalization

## Summary

The decisive lever for generalizing to never-before-seen cards is to encode each card from its *content* (mana cost, color, type line, P/T, keywords, and especially oracle rules text) rather than from a learned per-card ID embedding. Pure ID / one-hot / bag-of-cards encodings — used by the original DraftSim/DraftNet work (Ward et al. 2020/2021) — index a fixed vocabulary, so a new set is literally out-of-vocabulary and forces retraining a fresh model per set; they cannot produce any representation for a card that was not in the training vocabulary. The clearest direct evidence in this domain is Saxton 2024 ("Learning With Generalised Card Representations for Magic: The Gathering," arXiv:2407.05879), which compares random vectors, hand-coded numeric/categorical features, Sentence-BERT embeddings of oracle text, convolutional-autoencoder image features, and third-party usage "meta" features. Generalised content representations reach ~43% accuracy on entirely unseen cards trained on one small set and up to ~55% when trained on a ~100M-decision corpus (vs. ~22% random and ~one-hot which cannot generalize at all), while making little difference for *already-seen* cards. The standard recipe is: pull structured attributes from Scryfall bulk data, embed oracle text with a sentence transformer, optionally add an image autoencoder vector and usage meta-features, then concatenate and pass through an MLP card encoder. Recommender-systems research (zero-shot item rec, language-model priors, beeFormer) confirms the general principle and offers a refinement: text embeddings tuned/grounded on interaction data generalize to cold-start items better than off-the-shelf semantic embeddings.

## Approaches

### Learned per-card ID / one-hot / bag-of-cards embeddings (the anti-pattern)  
*Maturity: production-proven*

Each distinct card is an index into a fixed vocabulary; the model learns a free embedding vector (or a one-hot slot) per ID. DraftSim/DraftNet (Ward 2020/2021) encoded the collection as a bag-of-cards count vector of length = set size (e.g. 265 for M19), with dense layers sized to that vocabulary.

**How it applies:** Fundamentally cannot represent a card outside the training vocabulary: a new set's cards have no index and no learned vector, so the network has zero signal for them. Saxton 2024 states one-hot 'cannot be adapted for prediction on unseen cards' and that 'separate models would need to be trained for each new set.' This is the canonical cold-start failure mode for items.

**Tradeoffs:** Highest in-vocabulary accuracy and simplest to implement; captures idiosyncratic per-card strength the model learns from data. But zero generalization, requires full retrain each set, and vocabulary/output layer must grow over time.

### Structured-feature card encoder (numeric + categorical attributes)  
*Maturity: production-proven*

Encode mana cost/CMC as numbers, colors and color identity as multi-hot, type line and subtypes as categorical/multi-hot, power/toughness/loyalty as numerics (with sentinel handling for */X), rarity ordinal, and keyword abilities as a multi-hot keyword vector. Concatenate into a fixed-width vector independent of card identity.

**How it applies:** Because the feature schema is identical for any card, a brand-new card maps into the same space and gets a meaningful representation immediately. Captures the 'shape' of a card (cheap aggressive creature vs. expensive control spell) that transfers across sets. Saxton's 'hand-coded features' track is built exactly this way and is a core contributor to unseen-card accuracy.

**Tradeoffs:** Misses the semantics of unique/complex abilities not reducible to keywords (the bulk of what oracle text conveys); two cards with identical stats but very different rules text look similar. Best used as one component, not alone.

### Oracle-text embedding via sentence transformers (the key generalization lever)  
*Maturity: research-validated*

Run the card's oracle_text through a sentence-embedding model (Saxton 2024 uses Sentence-BERT / a sentence transformer) to get a dense vector capturing what the card actually does. Rules text is the richest signal for card function and is shared/normalized across reprints.

**How it applies:** A new card's never-seen ability is described in natural language the encoder already understands, so the model can infer function (removal, ramp, card draw, evasion) zero-shot. This is the single representation most responsible for semantic generalization in Saxton 2024; the zero-shot item-rec literature similarly concludes the key to zero-shot items is inferring embeddings from text side-information using pretrained LMs.

**Tradeoffs:** Off-the-shelf semantic similarity is not the same as gameplay/value similarity (two mechanically different cards can read similarly, and vice versa). Embeddings are large/static unless fine-tuned. MTG-specific jargon, templating, and numbers (e.g., '3 damage' vs '4 damage') can be under-weighted by generic models. Mitigations: fine-tune the encoder on MTG text or on interaction data (see beeFormer), or pool token embeddings of a domain-tuned LM.

### Hybrid concatenation: structured features + text embedding (+ image, + usage meta) into an MLP card encoder  
*Maturity: research-validated*

Concatenate the structured feature vector, the oracle-text embedding, optionally an image-autoencoder vector and third-party usage statistics, then pass through a small MLP (Saxton: 4 FC layers ~1024 wide) to a card embedding consumed by a downstream deck/pick model. This is late/early fusion of heterogeneous features, standard in recommender input layers.

**How it applies:** Combines complementary signals: structured features give reliable stats, text gives ability semantics, image/meta add extras. Saxton's combined 'Features + Meta + Image' representation reaches ~42.9% on unseen cards trained on one set (NEO) and ~55.4% trained on the full corpus, vs ~22% random. Critically, representation choice barely changes accuracy on seen cards but greatly improves unseen-card accuracy — fusion is what buys generalization.

**Tradeoffs:** More feature engineering and preprocessing; risk that one modality dominates. Usage/meta features (e.g., play rates) are themselves cold-start-limited for brand-new cards, so a model relying on them partially regresses to the ID-embedding problem. Keep meta optional/zeroable.

### Multimodal text + card art (image autoencoder)  
*Maturity: experimental*

Compress card art/full-image via a convolutional autoencoder into a fixed vector and add it to the representation. Saxton found a 1024-dim autoencoder bottleneck outperformed an aggressive 32-dim compression.

**How it applies:** Art correlates weakly with mechanics (creature types, set/faction themes, color) and is available for any new card, so it adds a small generalizable signal. In Saxton it was a minor positive contributor, mostly useful in combination.

**Tradeoffs:** Low information-per-parameter for gameplay value; art is decorative, not rules-bearing. Adds significant model size and a separate training stage for marginal gains. Optional rather than essential.

### Interaction-grounded / fine-tuned text embeddings (beeFormer-style) and LM-prior cold-start fusion  
*Maturity: research-validated*

Instead of frozen semantic embeddings, fine-tune the sentence transformer using interaction/pick data so the text encoder learns embeddings that reflect behavioral (pick/play) similarity, not just lexical similarity (beeFormer, RecSys 2024). Related: use an LM-derived text prior to initialize/regularize item embeddings so cold items inherit warm-item structure ('Language-Model Prior Overcomes Cold-Start Items').

**How it applies:** Directly targets the gap between 'reads similar' and 'is drafted similarly.' Because the *encoder* (not a per-card vector) is what's trained, it still produces embeddings for unseen cards from their text — preserving zero-shot ability while making the embedding space gameplay-aware. beeFormer also shows transfer across datasets/domains, hinting at training one card encoder across many sets.

**Tradeoffs:** Requires interaction data and a training pipeline that backprops into the text encoder (more compute, careful regularization to avoid overfitting to the current meta and losing zero-shot generality). Newer, less battle-tested than frozen-embedding pipelines.

## Recommendations

- Build a content-based card encoder, never a learned per-card ID embedding, if you need to handle new sets. Source attributes from Scryfall bulk data (Oracle Cards JSON) so you have a stable schema for any card.
- Make oracle_text + sentence-transformer embeddings the backbone of generalization. Start with a strong general sentence encoder (e.g., an all-MiniLM/all-mpnet-class model) over normalized oracle_text; this is what gives zero-shot understanding of new abilities.
- Concatenate a structured-feature vector with the text embedding before the MLP card encoder. Encode CMC/cost numerically, colors and color_identity as multi-hot, type/subtype categorically, power/toughness/loyalty numerically with explicit handling of '*'/'X', keywords as multi-hot, rarity ordinal. This is the fusion that Saxton 2024 shows buys unseen-card accuracy.
- Treat usage/meta features (play rates, win rates) as optional, zeroable inputs. They are themselves cold-start-limited for brand-new cards, so a model that leans on them re-introduces the very generalization problem you're trying to avoid.
- Add card art via an image autoencoder only if you have budget; expect it to be a minor contributor. Prioritize text and structured features first.
- Once you have pick/draft interaction data, fine-tune the text encoder on it (beeFormer-style) so embeddings capture draft-pick similarity rather than mere lexical similarity — but regularize to avoid overfitting the current meta and losing zero-shot ability.
- Evaluate with a held-out-set protocol (train on some sets, test picks on a completely unseen set) and report unseen-card accuracy separately from seen-card accuracy; Saxton 2024 shows representation choices look identical on seen cards and only diverge on unseen ones.
- Cache precomputed card embeddings keyed by oracle_id and refresh from Scryfall bulk data on each new set release; recompute text embeddings for any card whose oracle_text changes (errata).

## Open questions

- Does fine-tuning the oracle-text encoder on draft/pick interaction data (beeFormer-style) improve unseen-card accuracy in MTG specifically, or does it overfit the training meta and erode zero-shot generalization?
- Which text encoder is best for MTG: a general sentence transformer, a domain-fine-tuned one, or pooled embeddings from a larger instruction-tuned LLM? Saxton used a sentence transformer but did not exhaustively benchmark encoder families.
- How should numeric magnitudes in oracle text (e.g., 'deal 3 damage' vs 'deal 5 damage', mana values inside abilities) be encoded so the model is sensitive to them, given sentence encoders often under-weight numbers?
- How much does card art actually add once strong text+structured features are present? Saxton suggests marginal; this likely depends on set/theme correlations.
- What is the right way to represent multi-faced cards (MDFCs, split, adventure, flip) and planeswalkers (loyalty abilities) so each face's function is captured without conflating them?
- Can a single card encoder trained across many historical sets transfer to a genuinely novel mechanic that has no lexical analog in prior oracle text, or does truly new vocabulary still degrade zero-shot performance?
- Exact fusion architecture and quantitative cold-start gains of the 'Language-Model Prior' and zero-shot-KG papers were not verifiable from full text in this session (PDF extraction/403 issues) and should be confirmed before relying on their specific numbers.

## Sources

- [Learning With Generalised Card Representations for Magic: The Gathering (Saxton, 2024, arXiv:2407.05879)](https://arxiv.org/abs/2407.05879) *(paper)* — Directly studies generalization to unseen MTG cards. Compares random vectors, hand-coded numeric/categorical features, Sentence-BERT oracle-text embeddings, conv-autoencoder image features, and usage meta-features. Combined content representation reaches ~42.9% unseen-card accuracy trained on one set and ~55.4% on a ~100M-decision corpus (random ~22%); one-hot ID encodings cannot generalize and would need a new model per set. Representation choice barely affects seen-card accuracy but greatly improves unseen-card accuracy.
- [AI solutions for drafting in Magic: the Gathering (Ward et al., 2020, arXiv:2009.00655)](https://arxiv.org/abs/2009.00655) *(paper)* — Original DraftSim/NNet draft-pick work; encodes the collection as a bag-of-cards count vector indexed by card identity (length = set size, e.g. 265 for M19) with dense layers sized to that vocabulary. Analyses are single-set only and the authors flag generalization to diverse sets / unseen cards as future work — illustrating the ID-vocabulary cold-start limitation.
- [Predicting Human Card Selection in MTG with Contextual Preference Ranking (Bertram et al., 2021, arXiv:2105.11864)](https://arxiv.org/abs/2105.11864) *(paper)* — Siamese network learns a card embedding space by comparing cards in deck context; embedding dimension matters up to ~D=32 with diminishing returns by D=128. Shows the embedding-space framing for picks but still operates over a known card set.
- [beeFormer: Bridging the Gap Between Semantic and Interaction Similarity in Recommender Systems (RecSys 2024, arXiv:2409.10309)](https://arxiv.org/abs/2409.10309) *(paper)* — Trains sentence transformers on interaction data so text embeddings reflect behavioral similarity, enabling cold-start/zero-shot recommendation from item text and cross-domain transfer; outperforms both frozen semantic embeddings and traditional CF. Key insight for making oracle-text embeddings gameplay-aware while retaining zero-shot generalization.
- [Language-Model Prior Overcomes Cold-Start Items (arXiv:2411.09065)](https://arxiv.org/abs/2411.09065) *(paper)* — Uses LLM-derived text priors to overcome cold-start items, fusing content/text signal with collaborative embeddings so new items inherit structure from warm items. NOTE: I could not fully extract the PDF body (binary stream), so specifics of its fusion architecture and exact gain numbers are reported only from the title/search-level abstract, not verified line-by-line.
- [Zero-shot Item-based Recommendation via Multi-task Product Knowledge Graph Pre-Training (arXiv:2305.07633)](https://arxiv.org/abs/2305.07633) *(paper)* — Frames the zero-shot item problem as inferring item embeddings from generic side-information (titles/descriptions) using pretrained LMs — the same principle that makes oracle-text encoding the route to representing never-seen cards. Found via search; abstract-level only, PDF body not fetched.
- [Scryfall API — Card object, fields, and Bulk Data](https://scryfall.com/docs/api/bulk-data) *(docs)* — Likely attribute source: Card objects expose mana_cost, cmc, colors, color_identity, type_line, oracle_text, power, toughness, keywords, loyalty, rarity, produced_mana, and image_uris; oracle_text is the official, reprint-consistent rules text. Bulk files (Oracle Cards / Default Cards / All Cards) provide every gameplay field for every card, refreshed ~every 12 hours. ## Source verification

**Overall confidence:** high. All seven cited URLs are reachable and real. Six of seven are accurately described on the merits. The one accuracy failure is an author-name misattribution, not a content error: the flagship MTG paper (arXiv:2407.05879) is credited to 'Saxton, 2024' but was actually written by Bertram, Fuernkranz, and Mueller (IEEE CoG 2024 best student paper). This is important because the entire report's core narrative rests on this paper and the wrong author name appears throughout. Notably, the report itself does not even list 'Saxton' as an author anywhere in prose besides the citation tag, suggesting a fabricated/confused author handle. All quantitative claims attributed to that paper were verified exactly against the arXiv HTML full text: random baseline ~22% (1/15*sum 1/i), 42.87% on unseen NEO-trained, 55.44% on the 100M-decision corpus tested on unseen BRO, Sentence-BERT for oracle text, convolutional autoencoder with 32 and 1024 latent dims (1024 chosen), 4 FC layers x 1024 neurons, and the seen-vs-unseen accuracy finding. The recommender-systems sources (beeFormer, LM-prior cold-start, zero-shot KG) are all real and correctly cited, with the researcher having appropriately self-disclosed where only abstract-level verification was possible. The Scryfall docs page 403s to automated tools but is genuine; its substance is corroborated by search snippets and matches the well-known Scryfall schema. Two minor unverified specifics (D=32/128 in Bertram 2021; '265 for M19' in Ward 2020) are plausible and consistent with the literature but were not line-by-line confirmable this session due to PDF binary-extraction failures. No hallucinated sources or fabricated quantitative claims detected. Recommended fix: globally replace 'Saxton' with 'Bertram, Fuernkranz & Mueller' and double-check the two unverified numeric details.
