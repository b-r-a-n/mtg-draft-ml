# Datasets & Evaluation

## Summary

Two public datasets dominate MTG draft ML. 17Lands publishes large per-set CSVs from real MTG Arena play in three "views" — draft data (one row per pick, with the pack contents, the running pool, the chosen card, and the drafter's eventual event match wins), game data (one row per game with deck/sideboard/drawn-card indicators and a `won` flag), and replay data (turn-by-turn actions) — plus aggregated card_ratings (ALSA/ATA, GP/OH/GD/GIH/GNS win rates, IWD). I verified the draft_data schema directly from S3: e.g. FDN PremierDraft has 640 columns = 12 metadata fields + 259 `pack_card_<name>` + 259 `pool_<name>` columns. The Draftsim dataset is a single-set (M19, 265 cards) collection of 107,949 simulated drafts (CC BY 4.0) used by the foundational academic papers. Scryfall supplies card attributes (oracle_text, mana_cost, cmc, type_line, colors, keywords, rarity, etc.) via API and bulk JSON for feature engineering. Standard evaluation is top-1 pick-prediction accuracy vs the human pick (44–84% reported depending on model/set), per-pick-position accuracy, and pick-distance (MTPD); win-rate-based evaluation (agreement with high-GIH-WR picks, simulated deck win rate) and held-out new-set generalization are recognized but much less standardized, and popularity bias / meta drift / survivorship are the well-known pitfalls.

## Approaches

### 17Lands draft_data CSVs (pick-prediction training data)  
*Maturity: production-proven*

Per-set, per-event-type compressed CSVs at the S3 bucket 17lands-public.s3.amazonaws.com under /analysis_data/draft_data/draft_data_public.<SET>.<EVENT>.csv.gz (e.g. ...draft_data_public.FDN.PremierDraft.csv.gz). One row per draft pick. Verified header (FDN PremierDraft, 640 columns): metadata = expansion, event_type, draft_id, draft_time, rank, event_match_wins, event_match_losses, pack_number, pick_number, pick, pick_maindeck_rate, pick_sideboard_in_rate; then a one-hot/count block of 259 pack_card_<CardName> columns (how many copies of each card are in the current pack to choose from) and 259 pool_<CardName> columns (cards already drafted into the pool). Some sets also expose user_n_games_bucket and user_game_win_rate_bucket for skill filtering. Event types include PremierDraft, TradDraft, QuickDraft, Sealed, etc.

**How it applies:** This is the canonical supervised target: features = pack_card_* + pool_* (+ pick_number, pack_number), label = `pick`. event_match_wins (0-7) lets you weight/filter by drafter success (proxy for pick quality, mitigating pure popularity imitation). Card names as column suffixes mean you can join to Scryfall by name to get text/attributes, which is what enables generalization to unseen cards (embed card features rather than card identity).

**Tradeoffs:** Huge wide-and-sparse matrices (hundreds of name-suffixed columns per set; columns differ per set). Labels are human picks, so models learn human behavior incl. raredrafting/popularity bias, not optimal play. No card text included — must join Scryfall. Per-set files mean cross-set training needs a name->feature mapping.

### 17Lands game_data + card_ratings (win-rate signal & evaluation labels)  
*Maturity: production-proven*

game_data_public.<SET>.<EVENT>.csv.gz: one row per game with expansion, event_type, draft_id, game_number, match_number, build_index, rank/opp_rank, on_play, num_turns, num_mulligans, main_colors/splash_colors, opp_colors, won, plus name-suffixed indicators deck_<card>, sideboard_<card>, opening_hand_<card>, drawn_<card>, tutored_<card>. The aggregated card_ratings view (live JSON at 17lands.com/card_ratings/data?expansion=<SET>&format=<FMT>; fields verified: name, mtga_id, color, rarity, types, layout, seen_count, avg_seen (ALSA), pick_count, avg_pick (ATA), game_count, pool_count, play_rate, win_rate (GP WR), opening_hand_win_rate (OH WR), drawn_win_rate (GD WR), ever_drawn_win_rate (GIH WR), never_drawn_win_rate (GNS WR), drawn_improvement_win_rate (IWD)). GIH WR is considered the least-biased card-strength metric.

**How it applies:** Provides the win-rate ground truth to evaluate whether a bot's picks agree with empirically strong cards (e.g. correlation of pick order with GIH WR, or % of picks that take the highest-GIH-WR available card). game_data enables building decks and estimating deck strength / simulated win rate beyond pure imitation.

**Tradeoffs:** GIH WR biases toward controlling decks (longer games see more cards) and toward popular color pairs; GP WR is ~50% diluted by games where the card wasn't drawn. Win rates are confounded by drafter skill and archetype. Aggregated ratings are format/meta-specific and drift over time.

### Draftsim M19 dataset (academic benchmark)  
*Maturity: research-validated*

107,949 simulated Core Set 2019 (M19) human drafts from draftsim.com, 265 mechanically distinct cards. Released CC BY 4.0 at draftsim.com/draft-data; code at github.com/khakhalin/MTG. Each draft = 45 sequential picks (24 packs of 15). The Ward et al. paper used an 80/20 split (86,359 train / 21,590 test); the CPR paper reports 217,624,680 pairwise training examples derived from picks.

**How it applies:** The de facto academic benchmark for human-pick prediction. Single set keeps the card vocabulary fixed, which is convenient but limits generalization study. Used to compare RandomBot/RaredraftBot/DraftsimBot/BayesBot/NNetBot and the Siamese/CPR network.

**Tradeoffs:** Single set (no cross-set/unseen-card test), data from a simulator (not competitive Arena play), no game-outcome/win-rate labels (cannot evaluate deck strength), and contains raredrafting noise. Older (M19, 2018-era).

### Scryfall card attributes (feature source for generalization)  
*Maturity: production-proven*

REST API (api.scryfall.com) and bulk JSON downloads (data.scryfall.io via the /bulk-data endpoint: oracle_cards, default_cards, all_cards, rulings). Per-card fields verified live: name, oracle_id, mana_cost, cmc, type_line, oracle_text, power, toughness, colors, color_identity, keywords, rarity, set, collector_number, layout, produced_mana, legalities, image_uris, edhrec_rank, set_type, released_at.

**How it applies:** The key to generalizing to UNSEEN cards: instead of one-hot card identities, encode each card by its attributes/oracle text (e.g. text embeddings of oracle_text + numeric cmc/power/toughness + color/type one-hots). A model keyed on features rather than names can score brand-new set cards it never saw in training. Join to 17Lands by card name (and to Arena by mtga_id).

**Tradeoffs:** Name-based joins need normalization (split cards, double-faced layouts, alt-art/collector_number duplicates — prefer oracle_cards bulk to dedupe by oracle_id). Must respect Scryfall rate limits / cache bulk data. Oracle text is templated natural language requiring NLP to exploit.

### Top-1 / per-pick-position pick-prediction accuracy (primary eval metric)  
*Maturity: research-validated*

Mean testing top-one accuracy (MTTA): fraction of picks where the model's top choice equals the human pick. Also reported per pick number (1-45) to show the U-shaped difficulty curve (early picks easy on raw power, mid-pack hard due to synergy, late picks easy by elimination). Mean testing pick distance (MTPD): how far the human pick sits in the model's ranking (top-k proxy). Verified numbers (Draftsim M19 test set): RandomBot 22.15%, RaredraftBot 30.53%, DraftsimBot 44.54%, BayesBot 43.35%, NNetBot 48.67% (Ward et al.); SiameseBot/CPR 53.69% at embedding dim 2 and 83.78% (MTPD 0.2476) at dim 256 (Bertram et al.).

**How it applies:** Directly measures how human-like a draft bot is. Per-pick-position breakdown diagnoses whether a model captures synergy (mid-pack) vs raw power (early). MTPD is the practical top-k surrogate.

**Tradeoffs:** Measures imitation of humans, not optimal play — a perfect score reproduces human mistakes (raredrafting, popularity bias). High aggregate accuracy can be driven by easy early/late picks. Not comparable across sets (different card pools and difficulty).

### Win-rate agreement, simulated deck win rate, and held-out new-set generalization  
*Maturity: experimental*

Beyond imitation: (a) agreement with high-winrate picks — does the bot take the highest-GIH-WR available card, or does pick order correlate with empirical card win rate; (b) simulated/estimated deck win rate — build a deck from the drafted pool and estimate its win rate (Draftsim's own bot-battle work moves toward outcome-based comparison); (c) held-out NEW SET generalization — train on sets A..N, evaluate top-1 accuracy and win-rate agreement on a set released later whose cards were never seen, the true test for feature/text-based models.

**How it applies:** This is exactly the dimension the user cares about (generalization to unseen cards). The most rigorous protocol is leave-one-set-out / temporal holdout: train on older sets via Scryfall card features, test top-1 + GIH-WR-agreement on a brand-new set. 17Lands' per-set files + Scryfall features make this directly buildable.

**Tradeoffs:** No standardized public benchmark exists for cross-set generalization in MTG draft — you must build the split yourself. Deck-win-rate simulation needs a deckbuilder and a game engine/estimator (extra modeling, error compounding). Win-rate labels are meta- and skill-confounded; new-set win rates are noisy early after release.

## Recommendations

- Primary training data: pull per-set 17Lands draft_data from https://17lands-public.s3.amazonaws.com/analysis_data/draft_data/draft_data_public.<SET>.PremierDraft.csv.gz. Label = `pick`; features = the pack_card_<name> (candidates) and pool_<name> (already-drafted) columns plus pick_number/pack_number. Filter or weight by event_match_wins and user_game_win_rate_bucket to bias toward stronger drafters and reduce pure popularity imitation.
- For unseen-card generalization, do NOT key the model on card identity. Join every card name to Scryfall (use the oracle_cards bulk file from https://api.scryfall.com/bulk-data, dedupe by oracle_id) and represent cards by features: oracle_text embedding + cmc, power/toughness, colors/color_identity, type_line, keywords, rarity, produced_mana. A feature/text-keyed encoder can score cards from a set it never trained on.
- Build the generalization benchmark yourself with a temporal / leave-one-set-out split: train on older sets, evaluate top-1 accuracy AND win-rate agreement on a newer set whose cards were absent from training. There is no off-the-shelf public cross-set MTG-draft benchmark, so this split is your main contribution to rigor.
- Evaluate on multiple axes, not just top-1: (1) top-1 and top-k / mean pick distance vs the human pick; (2) per-pick-position accuracy (1-45) to confirm the model learns mid-pack synergy, not just easy early/late picks; (3) win-rate agreement — does the bot take the highest ever_drawn_win_rate (GIH WR) available card, or does pick order correlate with GIH WR from the card_ratings API; (4) optionally simulated/estimated deck win rate via game_data.
- Mitigate known pitfalls explicitly: popularity bias (humans imitate streamers/ratings — compare against GIH WR, weight by drafter win rate); raredrafting noise (rares taken for constructed value — the Ward paper shows this degrades top bots on strong/weak edge cards); meta/format drift (card_ratings and pick behavior shift over a set's life and across patches — segment by draft_time); survivorship bias (event_match_wins is only the final record; high-win drafters are overrepresented in late rounds — be careful aggregating by match wins).
- Use the Draftsim M19 dataset (draftsim.com/draft-data, CC BY 4.0) only as a single-set imitation benchmark to reproduce known baselines (NNetBot 48.67%, CPR/SiameseBot 83.78% top-1). It cannot test cross-set generalization or deck strength — use 17Lands multi-set + Scryfall for that.

## Open questions

- No standardized public held-out new-set generalization benchmark exists for MTG draft pick prediction; cross-set top-1 / win-rate-agreement numbers are not published, so absolute target performance for unseen cards is unknown.
- The exact, fully-documented column list and dtypes for 17Lands game_data and replay_data are not published as an official data dictionary; field names here were verified from sample files and community tooling (spells, Joel Nitta) and the live card_ratings API, but a canonical 17Lands schema doc was not located.
- How much does training/evaluating only on PremierDraft (vs QuickDraft/TradDraft/Sealed) bias models, given different player skill distributions and bot opponents in QuickDraft? Not quantified in the sources found.
- Quantitative comparison of imitation accuracy vs win-rate-optimal picking (i.e., how often the most-picked card differs from the highest-GIH-WR card) is discussed qualitatively (raredrafting) but I did not find a published number.
- Whether oracle-text-based card embeddings actually transfer to genuinely novel mechanics in new sets (vs only reskinned cards) is unverified — the CPR paper speculates the embedding approach is domain-agnostic but tests only single-set M19.

**Flagged claims:**

The cited blog says drawn-based metrics give 'much more signal' than GP WR but stops short of declaring GIH WR the single least-biased metric.
